# 小兔（XiaoTu）角色 demo

按 [`docs/骰子角色设计表.xlsx`](../../docs/骰子角色设计表.xlsx) 生成的角色 demo，由 `RitsuCharacterModTemplate` 展开（Mod id `XiaoTu`，RitsuLib）。

## 已实现（设计表的子集）

- 角色「小兔」，起始牌组：打击 ×5、防御 ×5、锈蚀骰子（S1）×1。
- 骰子系统 `XiaoTuCode/Dice/DiceState.cs`：骰子上限 5，普通/临时骰子，总骰点，重投（一枚/全部/按条件），押大，质押（到期归还），奇偶、相同点数、顺子判定。
- 金币可为负（下限 -1000，`GoldOps`），起始遗物「生锈的纪念骰子」：战斗开始 1 枚骰子，每欠 1 金币受到的攻击伤害 +0.5%。
- 卡牌 47 张：打击/防御/锈蚀骰子、好运打击/防御、骰子弹幕、塑料骰子、灌铅骰子，以及偶数/奇数是对的、兔急咬人、动如脱兔、单抽出奇迹、兑换筹码、质押系（保证不打人、保证让你打、倾囊而出、强制平仓、死当、暂时保管、售卖骰子）、铁斩波骰子、好运加码、加注、再加注、Pay2Win、饶我一命、大酬宾、金骰子、请给小费、投骰一击/护身、对子、奇数滚、偶数爬、乘胜追击、试手一掷、单双通吃、凑成双、清一色、否极泰来、顺子、孤注一掷、跟风、心想事成、666、仙人掌/流星锤/石头骰子，以及能力牌 单数福利、天选之人。

- 重投/获得骰子/失去金币事件：`DiceState` 统计，由起始遗物在每张牌打出后统一派发给 `IDiceListener`（能力牌与遗物）。回合开始自动投骰不算重投。
- 能力牌：安慰奖、飞来横骰、手续费、梭哈、焉知祸福、返利（战斗胜利时返还失去金币的 50%）、财大气粗（每 100 金币攻击伤害 +1，上限 5；设计表是“力量”，这里改用伤害加成）、气运护体（按最低骰点减免攻击伤害，用加法修正近似）、单数福利、天选之人。
- 其他牌：开幕雷击、掉包/假骰子、鱼目混珠/高仿骰子（衍生牌 Token 稀有度）、弱女子（`DiceState.Capacity` 骰子位）；锈蚀骰子：打出后本场战斗费用 +1，升级后额外重投所有骰子。
- 遗物：传奇骰子、商人的骰子、老虎机、会员积分卡（计数跨战斗保留）、被污染的教会金币（获得 500 金币并加入一张债务）。

## 说明

设计表里个别数值前后不一致时，按“效果”栏的基础数值、“升级后变化”栏的升级目标值实现（如偶数是对的 9→13）；Pay2Win 的升级写“抽牌 1→2”但效果没写抽牌，现按基础抽 1 张实现。骰子使用 `System.Random`，不与游戏种子同步。

## 构建与 PCK

本 mod 的 `XiaoTu.json` 声明了 `has_pck: true`，所以必须生成 `XiaoTu.pck`，否则游戏日志会报 “declares that it should load a PCK” 以及一大堆 `res://XiaoTu/images/...` 加载失败。

1. 在本目录新建（已被 .gitignore）`Directory.Build.props`，写入 `GodotPath`（Godot 4.5.1 mono 的 console.exe 路径）。
2. 运行 `dotnet publish`，它会编译并用 Godot 导出 pck 到游戏 `mods/XiaoTu/`。

## 实机测试（STS2_MCP）

- 已通过 MCP（127.0.0.1:15526）在游戏里用小兔跑过多场战斗，另验证了质押 3 回合后归还、金币为负（-55 时受到的攻击伤害 ×1.275）、重投事件类能力牌、梭哈/焉知祸福、衍生牌加入抽牌堆：起始牌组、遗物（战斗开始 1 枚骰子、回合开始重投）、约 40 张新牌的打出、金币扣除、质押、奖励选牌（小兔卡池）、商店均无报错。
- 修复：卡池原先没有能力牌，进商店会抛 “Can't generate valid rarity for merchant card type Power”（商店每种类型至少要有一张牌）；现加入 单数福利、天选之人 两张能力牌。
- 调试：`mods/XiaoTu/debug_cards.txt`（每行一个卡牌类名）存在时，每回合开始会往手牌里加最多 6 张并补能量，并在 godot.log 里打印 `[dice]` 骰子状态；删除该文件即关闭。
