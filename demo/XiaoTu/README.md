## 说明

设计表里个别数值前后不一致时，按“效果”栏的基础数值、“升级后变化”栏的升级目标值实现（如偶数是对的 9→13）；Pay2Win 的升级写“抽牌 1→2”但效果没写抽牌，现按基础抽 1 张实现。骰子使用 `System.Random`，不与游戏种子同步。

## 构建与 PCK

本 mod 的 `XiaoTu.json` 声明了 `has_pck: true`，所以必须生成 `XiaoTu.pck`，否则游戏日志会报 “declares that it should load a PCK” 以及一大堆 `res://XiaoTu/images/...` 加载失败。

1. 在本目录新建（已被 .gitignore）`Directory.Build.props`，写入 `GodotPath`（Godot 4.5.1 mono 的 console.exe 路径）。
2. 运行 `dotnet publish`，它会编译并用 Godot 导出 pck 到游戏 `mods/XiaoTu/`。

## 实机测试（STS2_MCP）

- 已通过 MCP（127.0.0.1:15526）在游戏里用小兔跑过 3 场战斗：起始牌组、遗物（战斗开始 1 枚骰子、回合开始重投）、约 40 张新牌的打出、金币扣除、质押、奖励选牌（小兔卡池）、商店均无报错。
- 修复：卡池原先没有能力牌，进商店会抛 “Can't generate valid rarity for merchant card type Power”（商店每种类型至少要有一张牌）；现加入 单数福利、天选之人 两张能力牌。
- 调试：`mods/XiaoTu/debug_cards.txt`（每行一个卡牌类名）存在时，每回合开始会往手牌里加最多 6 张并补能量，并在 godot.log 里打印 `[dice]` 骰子状态；删除该文件即关闭。
